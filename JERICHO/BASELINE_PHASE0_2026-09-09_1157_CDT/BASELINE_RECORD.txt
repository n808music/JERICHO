## ADDENDUM 2026-09-09 — the four errors, named (supersedes lines 56-62)

The claim above that all 4 of run1's unhandled errors originate in
MasterPlanTimeline.render.test.jsx is true for 3 of them, not 4.
run1_full.log:68698-68760, verbatim structure:

  #1  "Unhandled Rejection"  Timeout calling "onTaskUpdate"
      originated in tests/components/MasterPlanTimeline.render.test.jsx
      latest test: "does not show Unassigned label for full-horizon blocks
                    that have lane assignments"
  #2  "Unhandled Rejection"  Timeout calling "onTaskUpdate"
      originated in tests/components/MasterPlanTimeline.render.test.jsx
      latest test: "does not render constraint hash in normal Plan UI"
  #3  "Unhandled Rejection"  Timeout calling "onTaskUpdate"
      originated in tests/components/MasterPlanTimeline.render.test.jsx
      NO "latest test" line -- fired after the file's last test was documented
  #4  "Unhandled Error"      Timeout calling "onTaskUpdate"
      NO origin line at all. Not bound to any test file.

#4 is the one that is not a lost test result. Different header
("Unhandled Error", not "Unhandled Rejection"), no file attribution: it is
the reporter/RPC layer timing out after the worker had already lost the file
association. Same root cause as #1-#3, but it never corresponded to a test.

This is why 4 errors sat against a 3-result shortfall (4624 reported vs 4627
collected). The arithmetic is not a coincidence: 3 attributed errors, 3
missing results, 1 unattributed error. When applying the Errors-bucket rule,
read the header and look for the "This error originated in" line -- an entry
lacking one is infrastructure noise, not a test that vanished.
