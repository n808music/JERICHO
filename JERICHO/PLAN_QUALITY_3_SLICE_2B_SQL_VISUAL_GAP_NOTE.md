## Key Gaps

### 1. Missing "what"

The current generated plan still under-specifies the work object.

Examples of weak current phrasing:

- baseline in what
- project 1 about what
- project 2 about what
- project 3 about what
- proof artifact proving what

`portfolio-quality` is only a quality modifier. It is not the actual work
object.

### 2. Missing domain curriculum

The plan does not visibly preserve enough of the SQL learning payload.

Expected visible concept families include:

- joins
- aggregate functions
- CASE
- NULL handling
- subqueries
- CTEs
- date/time functions
- window functions

Without these, the plan has structure but lacks credible curriculum substance.

### 3. Weak project differentiation

The three-project shape is good, but the projects remain too anonymous.

They should read more like:

- structure raw data into relational form
- answer business questions with intermediate SQL
- produce advanced analytical reporting

not just:

- project 1
- project 2
- project 3

### 4. Weak interview-readiness operationalization

The current proof/review stages are directionally correct but still too
abstract.

They should surface concrete readiness outputs such as:

- timed SQL interview problems
- project walkthrough practice
- code explanation practice
- business reasoning explanation
- GitHub-ready presentation artifacts
