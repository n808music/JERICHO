# JERICHO Canonical 45 Family Rollout Plan

## Purpose

This plan turns the canonical 45 hardening matrix into a family-level rollout
strategy.

The point is to harden by shared execution grammar, not lane-by-lane
improvisation. Families unlock multiple lanes at once because they share
endpoint grammar, intake ambiguity patterns, deliverable grammar, block grammar,
dependency patterns, measurement models, and trust failure modes.

## Family Rollout Principles

- Highest leverage first
- Closest to already proven architecture first
- Family reuse before isolated lane work
- Preserve deterministic policy and lifecycle discipline
- Treat schedulable as distinct from trusted
- Treat reference families as regression anchors while degraded families are
  hardened

## Current Rollout Focus

Reference families already established:

- Creative / Release Media
- Capability / Credential
- Physical Progression

Next highest-leverage degraded family:

- Launch / Identity

## Rollout Sequence

### 1. Creative / Release Media

Why this family groups together:

- It is the strongest reference family for output-quality, title fidelity, and
  measurable block generation.
- The lanes share release-shaped deliverables, revision-heavy workflows, and
  publish-boundary sensitivity.

Lanes included:

- `TV / Series Writing`
- `Podcast Production`
- `Music Project Production`
- `Video Production`
- `Book / Longform Writing`

Shared endpoint taxonomy:

- concept -> structure -> creation -> revision -> release-ready output
- explicit release boundary: draft, publish-ready, published

Shared minimum intake sufficiency:

- target artifact
- completion boundary
- deadline or horizon
- starting state
- any release-specific constraint

Shared blocked vs draftable rules:

- missing release boundary is draftable only if the artifact is already clear
  and the remaining gap can be stated as an assumption
- missing artifact or missing release boundary with missing starting state is
  blocked

Shared required / recommended scope logic:

- required work is the core creative artifact path
- recommended work is supporting polish, release extras, and optional
  distribution assets

Shared deliverable grammar:

- outline, draft, revision, final package, release assets
- deliverable titles must stay concrete and episode/chapter/track/scenario
  specific where applicable

Shared block/measurability grammar:

- block titles must map to concrete artifacts or state changes
- measurable completion means artifact completion, revision completion, or
  release readiness, not just effort

Shared schedule lifecycle considerations:

- generate -> apply -> activate must remain authoritative
- release planning must not duplicate active work when the same draft is
  reapplied

Shared P.O.S. trust failure modes:

- assuming release readiness from generic creative motion
- confusing draft completeness with publish readiness
- overcounting batch work as completed release output

Family-level test strategy:

- use the podcast and TV lanes as the regression anchor for title fidelity and
  deliverable persistence
- use music/video/book lanes to prove the same boundary and measurability rules
  hold beyond podcast

Rollout priority:

- baseline reference family
- keep first as a regression anchor while degraded families are hardened

### 2. Capability / Credential

Why this family groups together:

- Both archetypes are threshold and evidence driven.
- The lanes share a learn -> practice -> proof grammar and a strong distinction
  between effort and qualification.

Lanes included:

- `Software Skill Acquisition`
- `Design Skill Acquisition`
- `Communication Skill Acquisition`
- `Technical Trade Skill Acquisition`
- `Creative Skill Acquisition`
- `Certification Exam`
- `Licensure Exam`
- `Compliance Training Completion`
- `Portfolio-Based Qualification`
- `Interview-Based Qualification`

Shared endpoint taxonomy:

- skill gain, proof artifact, exam pass, or qualification acceptance
- completion boundary is evidence-based, not vibes-based

Shared minimum intake sufficiency:

- target skill or qualification
- target proof standard
- deadline or horizon
- starting skill state or explicit assumed baseline

Shared blocked vs draftable rules:

- if the proof standard or assessment boundary is missing, the goal is degraded
  or blocked depending on how much can be assumed honestly
- study-only goals remain draftable only when proof criteria are explicit

Shared required / recommended scope logic:

- required work is study, practice, and proof-aligned tasks
- recommended work is extra drills, supplemental materials, or optional
  portfolio polish

Shared deliverable grammar:

- notes, practice artifacts, proof artifacts, submission packets, mock outputs,
  assessment readiness

Shared block/measurability grammar:

- blocks are measurable as study sessions, practice sets, mock scores, portfolio
  artifacts, or submission steps

Shared schedule lifecycle considerations:

- apply/activate must preserve evidence ordering
- re-generation must not replace existing proof-oriented blocks with generic
  study filler

Shared P.O.S. trust failure modes:

- confusing study time with proof of competence
- overpromoting rehearsal or practice to live readiness
- assuming baseline competence without explicit evidence

Family-level test strategy:

- pair study-heavy goals with explicit proof-heavy goals
- verify that the same readiness logic applies whether the endpoint is
  certification, qualification, or portfolio acceptance

Rollout priority:

- baseline reference family
- use it to regression-lock readiness and evidence discipline

### 3. Physical Progression

Why this family groups together:

- These lanes share a measurable progression grammar built on baseline, training
  load, recovery, and validated checkpoints.

Lanes included:

- `Strength Program`
- `Endurance Performance`
- `Weight Loss / Body Composition`
- `Rehab Return to Training`
- `General Conditioning`

Shared endpoint taxonomy:

- performance improvement, body-state change, rehab clearance, or capacity
  growth
- completion boundary must map to measurable change or benchmark completion

Shared minimum intake sufficiency:

- target outcome
- baseline or explicit assumed baseline
- deadline or training horizon
- injury/recovery context where relevant

Shared blocked vs draftable rules:

- missing measurable target is blocked or heavily degraded
- baseline uncertainty can be draftable only if the assumption is explicit and
  stable

Shared required / recommended scope logic:

- required work is training, recovery, benchmark checks, and progression control
- recommended work is supplemental mobility, nutrition, or extra conditioning
  support

Shared deliverable grammar:

- training blocks, benchmark tests, adherence logs, recovery sessions, readiness
  checks

Shared block/measurability grammar:

- every block should be measurable as a session, benchmark, recovery unit, or
  checkpoint

Shared schedule lifecycle considerations:

- active schedules must not casually duplicate progression blocks
- reschedule actions should preserve the continuity of the progression plan

Shared P.O.S. trust failure modes:

- baseline assumptions getting too loose
- recovery being treated as implied rather than measured
- progression being mistaken for final outcome

Family-level test strategy:

- verify that a measurable endpoint changes the plan shape
- verify that baseline ambiguity downgrades trust rather than inventing fitness
  assumptions

Rollout priority:

- reference baseline family
- use it to regression-lock measurable block and recovery discipline
- keep it as an anchor while Launch / Identity and the other degraded families
  are hardened

### 4. Launch / Identity

Why this family groups together:

- The lanes share launch boundary grammar, identity packaging, and pre-launch
  versus launch-phase ambiguity.
- They are the highest-leverage boundary-leak family because they can silently
  expand from a narrow launch into a broad operating model.

Lanes included:

- `SaaS Product Launch`
- `Consumer Product Launch`
- `Service Business Launch`
- `Marketplace Launch`
- `Local Business Launch`
- `Personal Brand Launch`
- `Business Brand Launch`
- `Product Brand Launch`
- `Artist / Creator Brand Launch`
- `Campaign Brand Launch`

Shared endpoint taxonomy:

- launch-ready, live launch, rollout complete, brand live, activation complete
- pre-launch setup must not be confused with launch execution

Shared minimum intake sufficiency:

- target offer or identity boundary
- launch horizon
- starting state
- launch channel or launch mode where relevant

Shared blocked vs draftable rules:

- if offer / identity / launch boundary is unclear, the goal is degraded or
  blocked rather than guessed
- launch prep can be draftable only when the boundary is explicit and the
  remaining assumptions are visible

Shared required / recommended scope logic:

- required work is boundary-aligned launch work
- recommended work is supporting polish, optional channel expansion, and
  post-launch extras

Shared deliverable grammar:

- strategy brief, offer package, identity assets, launch assets, activation
  plan, rollout pack

Shared block/measurability grammar:

- blocks should map to concrete launch assets, launch gates, or activation steps

Shared schedule lifecycle considerations:

- apply should place reviewable launch blocks
- activate should be the point where the launch plan becomes authoritative

Shared P.O.S. trust failure modes:

- assuming launch readiness from generic preparation
- letting identity polish become required launch scope
- counting pre-launch assets as evidence of live launch

Family-level test strategy:

- test one service launch, one product launch, and one brand launch case to
  prove the boundary holds across multiple launch grammars

Rollout priority:

- first degraded family to harden
- highest leverage because it covers 10 canonical lanes and the broadest
  launch-scope risk

### 5. Employment Pipeline

Why this family groups together:

- The lanes share the same staged conversion grammar: target -> materials ->
  outreach -> interview -> decision.
- Their biggest risk is that externally mediated outcomes get counted as
  internal progress too early.

Lanes included:

- `Corporate Role Search`
- `Remote Knowledge Work Search`
- `Creative Role Search`
- `Skilled Trade Role Search`
- `Career Transition Search`

Shared endpoint taxonomy:

- hired, interview-ready, offer-ready, transition-accepted

Shared minimum intake sufficiency:

- target role family
- deadline or horizon
- starting state
- qualification or portfolio baseline

Shared blocked vs draftable rules:

- unclear target role or unclear transition direction should block or heavily
  degrade
- draft plans are allowed only when the role family is explicit and the
  remaining assumptions are visible

Shared required / recommended scope logic:

- required work is targeting, materials, outreach, interview prep, and
  follow-through
- recommended work is optional networking polish, additional channel expansion,
  and extra interview rehearsal

Shared deliverable grammar:

- role profile, application tracker, outreach messages, interview prep,
  follow-up log

Shared block/measurability grammar:

- blocks should map to applications sent, outreach batches, interview prep,
  follow-up, or target list updates

Shared schedule lifecycle considerations:

- active schedules should preserve pipeline identity and not regenerate random
  application filler
- reschedules should keep the pipeline stage honest

Shared P.O.S. trust failure modes:

- counting applications as success without response evidence
- overpromoting interview readiness before the pipeline converts
- relying on assumptions about market response

Family-level test strategy:

- verify that the same readiness logic holds across corporate, remote, creative,
  trade, and transition variants

Rollout priority:

- second degraded family to harden
- high leverage but more externally mediated than Launch / Identity

### 6. Revenue / Capital Pipeline

Why this family groups together:

- These lanes share target -> outreach -> qualification -> conversion grammar.
- They are the most external-response-sensitive family and the easiest place to
  over-trust a schedule that has not yet produced live outcomes.

Lanes included:

- `B2B Service Sales`
- `B2C Product Sales`
- `High-Ticket Consultative Sales`
- `Retail / Local Offer Sales`
- `Subscription / Recurring Revenue Sales`
- `Friends and Family Raise`
- `Angel Raise`
- `Seed Round Raise`
- `Grant / Non-Dilutive Funding`
- `Sponsorship / Partnership Raise`

Shared endpoint taxonomy:

- qualified pipeline, closed revenue, committed capital, submitted funding,
  signed sponsorship

Shared minimum intake sufficiency:

- target amount or conversion target
- offer or funding narrative
- horizon
- target list or counterpart list

Shared blocked vs draftable rules:

- unclear target amount, unclear counterpart type, or unclear conversion
  boundary should degrade or block
- draft plans are allowed only when the external dependency is explicit and
  bounded

Shared required / recommended scope logic:

- required work is offer packaging, targeting, outreach, qualification, and
  follow-through
- recommended work is extra collateral, optional variants, and secondary channel
  expansion

Shared deliverable grammar:

- target list, narrative package, outreach sequence, proposal set, commitment
  tracker, diligence package

Shared block/measurability grammar:

- blocks should map to outreach batches, qualification steps, proposal work,
  submission steps, or commitment tracking

Shared schedule lifecycle considerations:

- active schedules must not be regenerated into duplicate outreach or duplicate
  proposal work
- post-activation changes should go through controlled reschedule or rebuild
  semantics

Shared P.O.S. trust failure modes:

- pipeline activity being mistaken for conversion
- commitments being assumed before they are real
- external counterpart uncertainty being hidden behind a confident schedule

Family-level test strategy:

- verify that sales, funding, grant, and sponsorship variants all keep trust
  provisional until evidence exists

Rollout priority:

- third degraded family to harden
- highest external-dependency risk and the strongest trust-gating requirement

## Recommended First Family to Harden

The first degraded family to harden is `Launch / Identity`.

Why:

- It is the most leverage-rich degraded family.
- It reuses the current intake, policy, output, and lifecycle discipline without
  needing new planner philosophy.
- It is the most likely place for silent scope expansion to re-enter through
  launch/readiness language.
