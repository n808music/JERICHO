observed to move WITHIN a capture -- run 1 vs run 2 of the same frozen

IF YOU GREP THE RAW LOGS BY HAND, USE grep -a
--------------------------------------------------------------
run1_full.log and run2_full.log contain bytes that make grep treat
them as binary. Without -a it suppresses matching output entirely and
returns NOTHING -- not an error, not a warning, an empty result that
reads exactly like absence. Measured: a pattern that sed found in these
logs returned empty from grep on the same file.

This is the pattern-match trap in its nastiest form. The usual case is
a populated result answering a question you did not ask; this one is a
null result answering no question at all. Every grep in this script and
in BASELINE_PHASEX_CAPTURE.sh carries -a for this reason.
